# VS01：Godot可编辑场景、界面美化与坐下互动

日期：2026-10-04。状态：根据用户大致认可及两项补充整理的设计稿，待用户审阅本文；未实施，不是已完成的功能清单。唯一项目目录：`E:\游戏创作\顾行舟`。

## 1. 用户意图与范围

用户希望同时使用Godot和VS Code开发、学习C#，不希望只能运行后在“远程”看到代码生成的界面。场景、人物、交互点、布局和动画应能在Godot本地场景中编辑，程序仍使用C#。主角真正坐到长椅上，由玩家主动选择是否“来一根”，不能自动抽烟。此前背景适配、手机与对白美化方向大致认可，继续保留修改空间。

本轮覆盖现有VS01：菜单、主界面、三个现实场景、主角、交互点、手机、对白、选择、设置与汤店回忆的可见编辑结构；统一任务提示、手机和对白外观；补小区长椅坐下及可选抽烟表现。移植不扩充三日剧情和地图，不改已有任务条件、汤店硬币与食物规则。后续吸烟buff另行设计，本轮没有数值加成、烟草库存或经济系统。

## 2. 方案比较与选择

| 方案 | 结果与代价 |
| --- | --- |
| 保持纯代码生成，仅给节点命名 | 运行时更好找，但本地编辑仍看不到布局，不能满足本次主要目的 |
| 所有东西固定写进场景，包括动态任务状态 | 本地直观，但动态内容易重复、剧情与表现耦合，不适合变化的邀请流程 |
| 推荐：可编辑场景＋C#逻辑＋独立剧情/数值数据 | 静态美术与布局存入场景，运行时绑定状态与生成必要动态内容；需要调整绑定并做回归，但便于学习和后续创作 |

采用第三种。不是改为GDScript，也不靠给所有脚本加Tool属性来强行在编辑器执行游戏逻辑。

## 3. Godot与VS Code分工

| 在Godot编辑 | 在VS Code用C#编辑 |
| --- | --- |
| 背景、人物与交互点位置、碰撞与相机边界 | 移动输入、最近交互点选择、任务与剧情分支 |
| 手机、对白、任务卡与按钮布局，字体主题和图标 | 手机内容更新、按钮行为、对白推进与焦点恢复 |
| SpriteFrames/AnimationPlayer动画、坐姿锚点与层级 | 坐下/抽烟/起身状态切换、取消与中断恢复 |
| 导出的交互标识、标题、描述和资源引用 | 数据校验、存档恢复、错误提示与测试 |

剧情正文继续由现有内容数据驱动，避免在图片、C#、场景三处重复维护同一段对白。运动和玩法参数保留现有数据来源，不新增另一套Inspector数值覆盖规则。

保存`.tscn`/`.tres`即可持久化美术和布局；修改`.cs`需要编译并重新运行验证，不承诺任意改动实时生效。配置Godot调用VS Code的外部脚本编辑器及项目内构建入口，使用已有.NET环境；不擅自安装额外插件。本地场景用于编辑，远程用于运行检查。F5验证完整游戏，不把单独F6运行任意子场景等同于完整剧情可用。

## 4. 场景组织与绑定

`Main.tscn`保存明确命名的世界显示容器与UI层。可编辑布局节点采用WorldDisplay、WorldViewport、HUD、TaskCard、InteractionHint、Phone、Dialogue、Choices、Settings和TransitionOverlay等稳定名称。Phone/Dialogue等实例使用独立场景，便于单独打开编辑；Main中按初始游戏状态隐藏弹层。单独打开UI场景时提供静态示例文字，游戏运行后由数据替换，不显示假任务。

`CommunityGate.tscn`、`ConvenienceStreet.tscn`、`SoupShop.tscn`保存背景、Player实例、碰撞边界、相机配置、静态NPC和具名交互点。长椅采用可复用Bench场景，保存交互点、SeatAnchor和安全起身位置。背景里原本画死的椅子需校准锚点，并根据坐姿增加必要的椅子前景遮挡层；不靠文字宣布“已经坐下”。

`Player.tscn`保存Artwork、CollisionShape2D、Camera2D和动画资源。待机/行走与新增坐下/坐姿/抽烟/起身动画保存在可编辑的资源中，编辑器可预览。保持原有走动碰撞与运动规则；坐姿视觉偏移独立于站立落脚点，不扩大或移动整张背景制造假动作。

`Phone.tscn`、`Dialogue.tscn`、Choice场景、`Settings.tscn`、`MemorySoupTable.tscn`及菜单保存各自可见UI、美术与示例布局。C#的Ready只获取具名节点、校验必要引用、连接信号和设置初始状态，不再无条件重建相同可见子树。编辑器预览不依赖正在运行的GameSession，也不读写玩家存档。

静态交互点的Id、Caption、Description、ActionId使用明确导出字段，Inspector可调整位置与描述；标识需校验唯一。张大炮到场仍由现有任务状态决定：场景中预存角色/交互实例，未到场时关闭显示和交互，而不是编辑器完全缺少这个角色。业务判断以状态为准，不能继续用“节点是否存在”代替到场条件。运行时确需产生的短暂提示明确命名，但不要求所有临时节点都永久保存到场景中。

保留MainView的World/Player/Dialogue/Phone等对外行为及已有事件标识；必要的内部路径调整同步更新测试，不能让测试继续检查已移除的匿名子节点。缺必需资源或引用时显示可理解的错误并阻止无效推进，不能静默进入半初始化游戏。

## 5. 背景与界面表现

背景覆盖实际游戏显示区域，保持人物和物件宽高比，较宽/较高窗口使用可视范围扩展与必要裁切。世界显示容器、内部视口、相机边界及UI锚点须一起适配，不能只改项目Stretch Aspect后留下固定1280×720的内部布局。不能把编辑器嵌入预览外侧留白当成游戏背景缺失；分别验证独立窗口和嵌入窗口。

取消目前整条顶部148/底部80高度深色遮罩，改左上紧凑任务卡和底部靠边操作提示。图像未变形，操作提示不能被裁掉。首轮保持现有世界尺寸与行走路径，不改变地图内容；实际扩大可见范围时相机边界要避免露出无背景区域。

手机采用磨损旧手机外框、灰蓝屏幕与暖色细节；信息区包含联系人、消息、任务与来电控制。图片负责边框和质感，动态文字与按钮使用真实Godot控件；不烘焙文字或仿制品牌标志。必要时使用可伸缩边框资源，避免较大字号把图框拉扁。

对白采用轻量深灰蓝面板、暖色细边、姓名牌及适度头像，正文与继续提示分离。独白使用更轻的样式。布局适应内容和20/24/32字号，长文字换行并保持操作可达，不硬性缩矮导致大字溢出。保留键盘导航、即时字幕、减少动效和旧手机叠层恢复行为。

## 6. 长椅与玩家自主选择

建议默认交互流程：靠近长椅按E，主角对准SeatAnchor播放坐下动画；到坐稳后显示小型选项“坐一会儿”“来一根”“起身”。默认焦点为“坐一会儿”，不自动选中或执行抽烟。该三项文案是本稿建议，可由用户改名。

“坐一会儿”关闭选项，保持坐姿与安静停留，不强制弹大段对白；再次按E可唤起选项。“来一根”关闭选项，播放一次有限的掏烟/点火/吸烟/吐烟表现，结束回到坐姿，不自动连续循环；坐稳后可以重新选择。“起身”播放起身动作并恢复走动。选项打开时Esc仅收起选项并继续坐着；选项关闭时Esc结束休息，正在抽烟则中止动作并安全起身，不留下输入锁。起身完成后Esc恢复原来的设置入口。

动作内部区分站立、坐下中、坐稳、抽烟中和起身中；连续按E不能启动多个动作。A/D在坐姿中不移动，站立后恢复原操作。手机和剧情弹层具有优先级：打开时暂停休息动作及其输入，关闭后恢复正确坐姿或已中断的站立，不吞掉接听操作。打开手机前先收起休息选项，收起手机后继续坐着，按E可以重新选择；不能因为原有Choice的Tab阻挡规则让休息选项永远挡住来电。坐着时场景邀请时钟仍按原自由活动规则推进；来电不会被休息永久阻挡。

坐姿是暂时的表现状态，不增加主线任务阶段或修改存档schema。存档保存可恢复的站立地面位置，读档默认站立；不保存半截抽烟动画。切场或读档前取消动作、清掉临时选项和烟雾，回到安全状态。原有首次观察的邀请心声仍可在坐稳后的“坐一会儿”首次确认时触发，取消不消耗该心声；坐下和抽烟本身不推进主线、不重复奖励。

本轮没有buff、烟数量或吸烟成本。后续用户确认数值系统后再讨论临时状态、冷却、消耗及非吸烟休息的替代选择，不通过本轮视觉动画暗中加入收益。坐姿锚点、吸烟烟雾和动画资源均在Godot可编辑，减少动效选项减少/关闭烟雾与闪烁，但必须保留清楚的坐下与起身反馈。

## 7. 资源、风险与学习

优先复用现有七张美术；主角新动作不能直接套用张大炮坐姿。缺少正式图集、手机外框和对白边框时使用内置生图，再检查实际透明、每帧裁切、角色一致性与脚底/坐姿锚点。新资源版本化保存，保留来源和提示，商用审核仍按既有资源政策执行。所有源文件、临时检查、截图、备份和新交付包只放在本工程内，不再写D盘或桌面。

两个主要风险是代码与场景同时创建造成重复节点、迁移后运行逻辑覆盖Inspector布局。约束是每种静态节点只有一个创建来源；布局属性由场景/资源主导，C#只更新必要运行状态。背景烘焙椅子的遮挡与身体比例须实际看图，不能仅靠测试计数通过。

学习演示应提供三个可复验小例子：在Godot移动Bench/SeatAnchor后坐姿同步移动；在Godot修改对白边框或手机布局，F5看到变化；在VS Code修改一次选项处理逻辑并编译，运行看到行为变化。补充“本地可编辑/远程调试”“场景引用/信号”“Export属性/数据来源”的中文说明，不将简单体验验证扩大为AI或大数据系统。

## 8. 验收条件与阶段边界

1. 不运行游戏，也能在Godot本地展开具名背景、人物、交互点和界面控件；单独打开UI场景可看到布局与示例内容，主角资源可预览动画。
2. Inspector位置、纹理、UI样式或座位锚点修改保存后可在运行中看到，并且不被Ready重建覆盖。
3. 三现实场景/手机/对白/回忆在1280×720、1920×1080及一组非16:9窗口检查。大字号文字和所有按钮可达，背景及人物不变形，任务卡不占整条屏幕。
4. 坐下后不自动抽烟；三选项可用键盘和鼠标操作；取消、连按、手机、来电、起身、切场、保存与恢复无卡住、瞬移到背景外或重复主线事件。
5. 新动作实际可见且符合椅子位置/遮挡，缺动画不能以文字通知替代并声称验收通过；减少动效路径同样可退出。
6. 既有规则、十二组引擎路径及工具负向检查回归；新增可编辑结构和休息行为检查。原测试基线只是迁移前证据，不能直接声称迁移后通过。
7. 不覆盖用户已有project.godot改动，不修改原故事集/私人照片，不擅自下载导出模板；新编辑器工程包与资源白名单单独验证。Windows独立EXE仍不在此设计的完成承诺内。

推荐开发顺序：可编辑场景与节点绑定 → 背景/HUD适配 → 手机与对白美术 → 长椅动作与自主选择 → 回归、实机截图和双工具学习示例。本文只规定方案与验收，不是实施计划；用户审阅确认本文后，再编写并审阅实施安排，然后开始代码修改。
