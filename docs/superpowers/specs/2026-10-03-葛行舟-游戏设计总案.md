# 葛行舟｜游戏设计总案

V0.2设计评审稿｜2026-10-03｜Godot .NET / C# / VS Code

## 1. 创作目标与成功标准

沿用：开发一款可商业发行的2D半开放叙事生活游戏，讲人生、爱与成长，同时学习C#、算法、AI和数据工程，为2027年6月毕业求职积累作品。商业盈利是目标，不是收入保证；求职能力用实际作品和可复现实验说明，不以技术名词数量衡量。

北极星体验：葛行舟回到已经拆迁的故乡，被张大炮的结婚邀请拉进三天的日常。玩家在互损、帮忙、吃饭、旧手机和未完成的歌中理解：自由不是不需要别人，成长也不是放弃自己。他终于愿意选择，并承担选择的代价。

首段成功标准：第一次接触游戏的人能移动、读懂邀请、把喜糖递给朋友、触发粉丝汤回忆并返回现实；无需解释界面；不接电话仍能推进；退出后能继续；不少于两种行动得到不同反馈，但不改写历史事实。目标15—25分钟，不要求这一时长成为硬性计时任务。

## 2. 方案选择与范围

| 方案 | 得到什么 | 代价 | 判断 |
| --- | --- | --- | --- |
| 小型自由地图＋固定三日主线＋关键互动 | 保留行动感、熟人生活和情感操作 | 需要移动、任务、存档与场景切换 | 推荐，契合已有讨论 |
| 主要采用视觉小说＋少量互动 | 更快完成叙事 | 自由探索与生活感较弱 | 可作缩减方案，不直接替代已选方向 |
| 首版就做多城市开放世界＋全NPC＋在线AI | 大量自由内容 | 美术、内容、测试和成本明显膨胀 | 后置，不作为首版规格 |

分层而不是一次实现全部系统：

1. **VS01首段切片**：安置小区、邀请、Hey哥、粉丝汤和少年硬币回忆；移动、交互、手机消息、任务、存档、少量本地事件。
2. **三日Demo**：加入假面、家庭土地支线、酒店试音、婚礼、旧爱回忆和原声合唱，目标约1—2小时。具体内容可根据第一轮测试缩减。
3. **完整版扩展**：更多朋友、马鞍山、无锡、骑行片段、多个人生后日谈；重新估算工作量，不承诺首个Demo全部包含。

首段不做战斗、复杂经济、AI生成对话、Android、手柄、Steam接入、完整婚礼。纯横向移动先验证；街道纵深属于后续独立增量。不存在刷级、饥饿、装备掉落、每日签到或抽卡系统。

## 3. 体验支柱

- **生活不是选项菜单**：停留、递东西、收起手机、推硬币、帮忙都是表达；普通任务仍清楚说明，不以猜设计者意图取代可用性。
- **熟人互损里有照顾**：幽默约占整体七成，沉重约三成；这是写作导向，不是逐句配额。
- **取舍产生收尾，不制造灾难**：陪家人导致婚礼任务没完成，朋友会补位；玩家面对具体小麻烦，不因支线选择让婚礼失败。
- **旧事不能重写，理解可以变化**：分手和身份事实固定，玩家改变当下行动、叙述与未来选择。
- **真相可错过，线索公平**：秘密不是集齐碎片后的解锁奖励，不显示亲属真相进度条。

## 4. 核心循环与操作

在小地图自由走动 → 观察人和物 → 对话/交付/操作 → 获得关系反馈或线索 → 选择深度行动 → 世界进入下一时段 → 返回共同主线。

键盘暂定：A/D或左右键移动；Shift加快；E交互/确认；Tab打开手机；Esc返回/暂停；鼠标用于手机与场景物件。关键交互必须提供键盘替代。攻击与闪避键到动作增量时再启用，婚礼不可攻击宾客。

提示分三级：靠近出现动作名称；数秒内未理解时出现一次操作提示；可选辅助模式直接标示互动目标。情感场景不显示“好感+5”，辅助模式也不告诉玩家“正确感情答案”。

移动、读字幕、看普通手机内容不扣行动。仅在第二天关键行动开始前明确提示“将进入下午/傍晚/夜晚”，允许取消；不按真实秒数扣除剧情时间。

## 5. 剧情结构与角色约束

| 章节 | 明确事件 | 自由内容 | 情绪收束 |
| --- | --- | --- | --- |
| 第一天：重新接上 | 邀请、送喜糖、粉丝汤、旧手机、入睡 | 朋友片段、旧招牌、手机入口顺序 | 以前的声音仍有人记得 |
| 第二天：有限的时间 | 三次关键行动、夜晚酒店试音 | 婚礼差事、送饭、荒地、奶奶、旧址 | 陪伴与承诺都需要承担 |
| 第三天：向前一步 | 接亲、宴席、停电、原声歌 | 婚鞋方式、红包线索、人与人收尾 | 不再只唱给失去的人 |

葛行舟：表面幽默，内里孤独与停滞；服装为短辫、旧牛仔外套、背心、链裤、马丁靴。做过驻唱、乐队、骑行、游戏工作、旅行和读研。不能以“懒惰”单词解释全部经历，也不把他写成等待女主治疗的人。

林知微（林老师）：温柔外表下有摇滚与艺术气息；主动靠近他，看见脆弱，也有自己的边界和未来。吉他、项链和旧手机是关系留下的物件。舞蹈段落保留葛看不懂却装懂、她笑着揭穿的真实笨拙。大学琴房分手、多年后最后电话既定；她后来幸福，真实主线不提供追回她的奖励。幻想如制作必须明确标注“如果”，首段不制作。

父亲/母亲：实际为从小抚养葛的堂哥、堂嫂；对主角不是新秘密，对玩家可以隐藏。父亲服装厂生意下滑后做保安；母亲抑郁与父母爱情细节等待访谈，不补写成事实。关键表达是“你过好自己，家里的事我来承担”，不把照护者奉献等同于主角无需回应。

奶奶：仍种荒地，有自己的判断与行动。冲突不能靠打赢解决，她能叫停。隐藏支线将祭扫与旧合照结合，近乎确认身世；任何未收集的线索都不能在结尾强制揭露。

张大炮：发小、点子王、爽快大方，车里装婚庆杂物而非炫富。嘴贫与操心并存。新娘是关系中的主体，不是“主角朋友已经成功”的布景。

假面：杭州测试工作、家庭条件较好、不断相亲；口头禅“日”、旧礼物、会员续费形成回响。正式发行使用虚构软件与无标车，不照搬真实界面。

Hey哥深层经历、李去完整内容待补充。Hey现有玩笑足够首段教学；李去只预留内容槽，不在首段出现，不为公开Demo写一句“占位NPC”敷衍故事。

## 6. 记忆、手机与情感互动

手机功能：主线消息、相册、录音、旧空间、联系人、乡音词典；首段仅消息与任务页。普通照片/文字不必都进入独立可玩关卡。

旧手机卡顿是叙事效果而非随机破坏操作。对重要输入，先确认操作再播放故障表现；不会吞掉存档或强制发送错误信息。设置提供“简化手机故障”和“减少闪烁”。首段不引入随机误触。

粉丝汤回忆：硬币碰桌、汤气切换、少年凑钱、最后一块食物；回到现实后成年张大炮用不同措辞回忆。历史不变，反应改变。琴房可用“合上琴盖、走到门口、停下”讲犹豫；最后电话以完整倾听与退出收束，不加入复合判定。

隐藏互动有可见物理反馈、可复盘环境线索；涉及故事推进时至少一种显式可达方式。没有操作失败QTE惩罚爱情。

## 7. 时间、轻动作与结局

第二天固定三个行动点，详见数值文档。旅行和阅读不耗点；关键陪伴与差事耗点。夜晚试音固定，不额外扣点。承诺可错过，婚礼不失败。

动作系统属于三日Demo后续增量：现实冲突可动手、谈、停手或找人；不允许在街上攻击任意NPC。心理场景复用输入和状态机，但非战斗解决同样有效。第一夜空心人仅远处存在，无可击败Boss。

未来结局采用“玩家明确选择计划＋此前行动给出可解释反馈”，不由隐藏分数擅自分配职业。工作并继续音乐、游戏创作、可持续音乐、带计划旅行、继续停滞均不做高低排名。首段只以一次老友回应收束，不生成终身结论。

## 8. 技术设计与模块边界

采用Godot .NET版、C#、VS Code，先Windows本地离线。官方说明标准Godot编辑器不含C#支持；C#的Android支持仍标为实验性，因此Android单独验证，不承诺直接一键移植。[Godot官方C#文档](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/index.html)。

本机已读到.NET 8与10 SDK；尚未定位本项目应使用的Godot可执行文件。其他项目中的版本声明不作为安装证明。开发前核验编辑器、Godot.NET.Sdk、目标.NET和导出模板的匹配组合，并锁定版本；此处不虚构“最新版本”。

| 模块 | 单一职责 | 对外接口与依赖 |
| --- | --- | --- |
| PlayerController | 输入、横向运动、可操作锁 | 发交互意图；不直接推进剧情 |
| InteractionSystem | 候选目标、距离、一次性动作 | 调用目标操作，返回成功/不可用 |
| DialogueRunner | 手工台词、节点条件、字幕 | 读事实与任务；提交剧情事件 |
| QuestService | 主线阶段、道具和已完成事件 | 按稳定ID处理事件，重复提交无重复奖励 |
| WorldState | 日/时段/人物位置/关键事实 | 存档权威状态，其他模块只经接口修改 |
| PhoneController | 信息与应用视图 | 展示任务和数据；不另存一份任务真相 |
| SceneFlow | 现实/记忆进入返回 | 记录返回场景、位置和可操作状态 |
| SaveService | 版本化快照、读取、备份恢复 | 在安全检查点保存WorldState |
| LocalEventRecorder | 可选本地行为记录 | 不驱动关键剧情；关闭不影响通关 |

事件流：输入 → 交互目标 → 剧情事件 → 任务/世界状态更新 → 界面刷新 → 安全点保存；可选记录在旁路。场景节点不承担持久化真相。

内容用稳定ID的数据驱动：角色、台词、任务、回忆入口和事件独立于C#；中文显示名改动不改变ID。首段只使用本地JSON/引擎资源，不同时叠加SQL数据库、网络后端和大模型。

存档结构至少包含schema_version、content_version、scene_id、返回位置、quest_stage、已发生事件集合、物件状态、phone_state、时段。行为记录不是恢复存档的依赖。迁移失败保留原档，提示加载备份/开始新档，禁止静默重置。目录、坏文件、磁盘写入失败都要给玩家可读提示。

## 9. AI与数据：学习辅助，不抢游戏优先级

首段只建立可选、匿名、本地事件字典，记录特定交互，不录制音频、文本输入、联系方式或真实家庭资料。用户可关闭、清空、单独导出；上传测试数据必须另获参与者明确同意。小样本仅用于发现可用性问题，不称“人格预测”。

随后用Python/SQL清洗和分析：转场成功率、流程完成、操作重复、提示使用。模拟数据与真人数据严格分开；没有真实样本时不捏造玩家结论。

空心人AI是后续独立实验，采用虚构事实库、话题边界、离线预写台词与超时回退；真实人物NPC保持人工台词。无网络时核心游戏全部可运行；AI实验不成为发行依赖。

## 10. 视觉与音频基线

半写实比例像素化2D，现实偏冷灰、记忆偏暖；区分不只依赖颜色，采用日期、环境变化与声音。美术规格和缺口见资源文档。

已有六张角色概念图仅用于造型参照，未发现行走/交互动画、地形图块、UI或原声音频。最先做可读灰盒，再以角色参考生成必要场景概念或找许可明确的通用资源。生图不会自动得到可用帧动画；正式贴图需要统一尺寸、调色板、透明背景、落脚点并实机检查。

原创吉他主题优先；无曲时用临时节拍/短音，不把他人商业歌曲当可发布占位。暂不用现实手机/车标/社交软件截图。真实女主照片不用于公开素材。

## 11. 非功能与验收

暂定基准为用户当前Windows笔记本、1080p显示；不是全平台最低配置承诺。目标60fps；字幕可调、无配音也能理解、键盘能完成关键操作，关闭音乐不丢操作提示。从菜单到可操作目标≤10秒，转场目标≤2秒，实测后修订。

必须验收：

- 电话接听/忽略/打开再关闭均能到达邀请结束；不重复刷出喜糖。
- Hey交付后退出重进不丢任务、不重复交付；走开不被对话永久锁住。
- 汤店进入回忆再返回，角色位置与操作状态正确；钱币/食物的重复操作不重复计分。
- 手机关闭、暂停、断档恢复不吞输入，不触发下一章错误。
- 故事辅助模式、全键盘、字幕放大情况下完成流程。
- 关闭行为记录依然通关；坏记录文件不会破坏主线存档。
- 新增资源的来源/许可有记录；公开版本不含现实个人照片、录音或真实关系表。

验证方式分为规则单元测试、Godot场景集成检查、Windows可运行构建冒烟测试和小样本试玩。设计文档不能替代这些实际结果。

## 12. 风险与本轮评审边界

本案冻结的是首段范围与系统责任，不冻结所有人生故事。三日总体属于方向规格，每个后续章节在实现前细化其可玩内容；完整版和AI不混进首段实现计划。

需用户确认：是否接受先做VS01。原第238题婚鞋方式留至第三天细化，本轮建议多种非伤害方式＋翻乱后收拾，但不视为已经选择。父母爱情、婚俗、李去内容不阻塞VS01。

本轮只交付设计与素材审计，不创建伪装可运行的Godot工程。书面设计获批后，下一步制定可执行的实现计划，确认执行方式，再进入C#开发。
