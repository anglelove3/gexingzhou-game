## 1. 已认可的意图与取舍

用户希望玩家不只左右走和读大段文字，而能在生活场景中探索、发现物件、通过动作与人物建立联系；同时人物与桌椅协调、手机接近熟悉的微信聊天体验、任务有独立界面。仍讲人生、爱与成长，保留地方生活与幽默，不把游戏改成刷物品或战斗。

采用“保留暖色插画风格、增加2D地面纵深”的路线。继续横向成本较低但不满足探索要求；完全改俯视角会大范围重做美术与演出；本案不转全3D、不更换引擎。

先做汤店样板，验证四向移动、脚下碰撞、前后遮挡、桌椅与人物比例、坐下起身、小型对白与三处鼠标观察点。验收样板后再单独设计并实施其他地图、任务日志和微信式手机。不把整体方向认可解释成所有后续子项目已具备实施规格。

用户未要求照搬某一具体微信版本，也未指定新任务奖励数值。本案以熟悉的聊天阅读结构和叙事见闻为目标，不连接真实账号，不引入现实聊天数据；隐藏物件不奖励金币、能力或善恶分数。

## 2. 工程核对与本次边界

基线已具有首段任务链、三种汤店回应、四币回忆/三种食物反馈、手机/暂停/存档/收尾及具名场景节点。原R1—R6是已完成历史，不重复实施；原文档中“手机重做/探索后置”由本次新方向分期承接，不改写历史。

已确认的问题：

- PlayerController仅计算水平轴，Velocity.Y=0；MovementModel是标量速度模型。
- InteractionCandidate与InteractionPolicy按X距离选择，不能原样用于有纵深的场景。
- 三张现实地图使用横向Floor/边界；主要家具画在完整背景内，无法仅加按键解决绕行和遮挡。
- Dialogue.tscn固定底部面板高度约278像素，720高视图中短句也占大块区域。
- 汤店使用不同素材缩放与座位锚点；张大炮坐姿约57世界像素高，站立主角基准68，桌椅又来自背景，缺统一人物/家具比例体系。
- SaveRepository同时将PlayerPosition.Y与回忆ReturnContext.Position.Y严格限定为280。放开移动却不改存档规则将导致合法游玩位置保存失败。

用户截图证明静态比例不协调；起身时是否还存在跳帧、尺寸突变或锚点跳位，尚未动态复现，不能在设计阶段宣称某单一原因已修复。

本子项目不新增地图、不写三日婚礼、不新增角色真实经历、不改三种回忆结果；不实现微信界面、独立任务日志、桌底惊吓事件、抽烟buff、点击地面自动寻路、物品背包、在线AI或商业发行包。现有两项Minor（数字字符串Kind、来电音尾段）继续保留为独立待办。

## 3. 地面探索与操作

### 3.1 汤店样板

汤店改为有明确室内地面深度的插画场景，不允许角色在墙面、招牌或桌面上自由滑行。新参考世界画布960×540；相机按ViewBounds适配窗口并限制在场景内部，16:9可显示整体，4:3允许横向跟随，不拉伸人物，不露出未绘制区域。

世界坐标以脚底为角色原点。采用固定角色尺度，不用随Y缩放的伪透视掩盖桌椅错误。男主同一深度的站姿参考高度96世界像素；不同人物可有体型差异，但张大炮不能因素材来源不同显得像缩小的成年人。桌面离地高度以站高的约0.45—0.50、普通椅面约0.28—0.32为首轮美术试调基准，最终以同屏坐姿自然度验收，不作为真实家具尺寸。

SoupShop中预存可编辑的WalkableArea、多边形障碍、Actors、Props、Foreground、座位/入口/退出/回忆返回锚点。地面主通路参考范围X=24—936、Y=360—520；家具占地区域作为扣除区域。美术按此地面与摆位制作，不能先生成无法通行的大图，再任意把碰撞贴上去。主通路须连接入口、桌边站位、三处观察点及出口，局部宽度足以容纳角色脚部碰撞形状和滑行。

障碍只阻挡真实占地：桌椅、柜台、盆栽、墙/关闭入口等。脚部使用小胶囊/圆角碰撞形状；头部和上身不是整个实物占地。靠墙可沿边滑行，不能穿桌、不因花瓶的空白透明区域被挡住。家具、角色按脚下/占地基准参与同层Y排序；需要遮住身体局部的桌沿使用独立前景片，不能只打开Y排序就认为完整背景中的家具已可遮挡。

美术节点、碰撞形状、锚点、观察热点均保存于.tscn；Godot本地场景树可以选中、移动、替换资源。C#绑定行为，不在启动时生成整套隐形地图。

### 3.2 输入与移动

WASD/方向键控制上下左右，可同时按两轴斜行；方向向量归一化，斜向不加速。Shift继续加快，步行112/快走168、加速800/减速1200先沿用现有数值作为试调，不宣称已是最终手感。

行走动画至少前、后、侧三个朝向，侧向可镜像；各方向共享脚底原点、相同体型、匹配步频。静止时保留最后朝向。脚步按真实二维移动距离触发，撞墙不原地发脚步，不继续用仅X位移判断。

对白、手机、暂停、回忆与坐姿继续互斥移动。按键从界面返回后不留下持续移动或焦点；斜行、失焦、减少动效均有对应检查。玩家仍用E操作附近对象，鼠标可观察物件；本阶段不将点击地面解释为自动行走。

### 3.3 渐进接入

WorldView显式区分Horizontal与Depth2D模式：本阶段仅汤店Depth2D，小区和便利店街维持现有横向移动。共享角色/交互代码按场景模式处理，旧场景不能因删Floor绑定或通用Y排序被破坏。汤店通过后，后续子项目再将另外两张地图转为Depth2D；整体目标仍是现实探索地图都可四向活动。

硬币回忆继续桌面近景鼠标/键盘互动，不增加角色走路。汤店内退出/返回也继续由原故事条件控制，探索不能绕过交喜糖或回忆付款。

## 4. 人物、桌椅与动作

样板重做汤店分层美术和同尺度座位组合，男主、张大炮、桌、椅、脚下阴影使用同一尺寸基准。保留人物已批准造型与幽默性格，优先读项目内资源；不足时实施阶段再生成/选用资源并记录来源、完整提示、许可说明和哈希。此设计阶段不生成正式资源。

张大炮正常坐在对面：臀部落在椅面，头和上身明显高于桌面，腿部自然处于桌下，不能以当前缩小/低置的坐姿充当桌底彩蛋。桌底捡物件并突然出现的笑点留待后续独立批准，不增加自动惊吓或强制QTE。

男主坐下：走近桌边→沿无障碍短路径到StandAnchor→转向座位→坐下→坐稳→原有汤店对白/行动选择。玩家偏离很远时只提示靠近，不直接跨桌传送；短路径被阻挡时取消就位、恢复自由活动并提示，不发汤店事件。

起身：身体前倾→双脚撑地→站直→回到合法StandAnchor与行走资源。静止姿态不靠把站立整图平移来替代坐姿。动画逐帧校准脚底/臀部锚点；切换行走与坐姿资源时没有体型突变、脚部滑动或突然横向跳位。

SoupSeatController继续管理汤店姿态，RestController管理长椅，二者互斥。三种动作仍对应eat/set_chopsticks/check_phone、soup-response-1；选择确认后故事事实提交一次，动作显示再接原分支对白，异常中断有恢复路径，不能重复提交奖励。沿用会话代次阻止过期动画回调。

打开手机冻结动作并恢复正确姿态；Esc在选项打开时先关闭选项，再按才起身；起身期间不重入选项。减少动效使用稳定姿态与短过渡，不强制观看完整动作。保存使用合法站位，不存动画帧、视觉偏移或Tween；读档恢复站姿。

桌沿需正确遮挡腰腿、不遮脸；喝汤时碗与手相接，递筷子有桌上落点，看手机与手机亮光靠手部。新资源不能仅通过“动画存在”检查，必须同屏检查接触点与动作连贯。

## 5. 对白样式样板

主要对白改为轻量底部字幕条：姓名和两至三行文字、小型继续提示、低存在感边框；在1280×720/默认字号24下普通短句目标高度约120—170像素。此范围是正常短句布局目标，大字号32/较窄视图可增高，不能缩小用户字号或裁掉文字来满足固定高度。

短闲聊可用人物上方小气泡，但只作非阻塞提示；首轮正式任务对白仍由唯一DialogueController推进。气泡和底部字幕不同时呈现同一句，不新增会重复推进剧情的第二对白会话。气泡需避开视口边缘与人物脸部。

Thought/Spoken/Narration元数据继续有效：讲话显示姓名，心声与旁白使用轻量区分；不从台词前缀猜说话人。长句分为阅读单元，不删改剧情、不改完成事件。字体20/24/32均可阅读，长文本有可访问的滚动或分页操作；选项和继续提示不挤出屏幕。

底部安全区与人物动作区分开；汤店关键坐姿不能被字幕完全遮住。HUD默认只保留一条简短目标，可折叠当前大卡片；还不实现J日志。布局变化发生在共享UI，因此验收也覆盖未改移动的小区、便利店街和三种回忆返回对白。

## 6. 三处观察点与鼠标交互

只做三处：旧招牌（沿用sign）、菜单（沿用menu）、柜台旁手写便条（新增soup.note）。先用现有已确认的招牌/菜单描述；便条写生活性短句“先坐，汤马上好。”，不编造人物过去或身世证据。三处是可选观察，不阻塞主线，不是必须搜齐的奖励任务。

热点对应可见物件的实际位置/轮廓，悬停轻描边和短标题。物件须在当前可见画面中且未被前景遮蔽；鼠标坐标转换通过实际SubViewport和相机变换，不能把窗口像素直接当世界坐标。点击UI不透传到场景，手机/对白/暂停打开时场景热点不响应。

纯观察可以远看；需要拿取或操作的对象必须满足二维距离和遮挡条件，本阶段没有拿取物品。只有移动到附近时E才选择可到达对象；目标切换保留迟滞和重复按键保护，不能按X距离隔着桌子触发座位。

首次完整读完观察后记录一个稳定发现ID；Esc中途关闭不消费首次发现。重复观察可读原描述但不重复奖励/记录，不调用主线完成事件。三个发现ID为soup.sign、soup.menu、soup.note；它们只进入新存档的DiscoveredIds，不冒充原CompletedActions里的主线事实。

## 7. 存档兼容与错误处理

四向探索改变了合法坐标和观察记录，因此本案采用新schema_version=2、content_version=vs01-0.2，沿用既有SceneId、Stage、机会ID和三种回忆结果。新档写入单独的user://saves/vs01-explore-v2；旧user://saves/vs01文件只读，保留旧版回退时可用的原档。此版本/目录方案已随本书面设计获认可，但尚未实施。

v2新增DiscoveredIds（有限集合、已知ID），位置按场景模式/有效地面校验：尚未改造地图仍使用原范围和Y=280；汤店使用有效地面、障碍占地和明确安全锚点。回忆本身不变成四向地图，回忆ReturnContext允许汤店新坐标并要求可恢复合法站位。

旧档升级是明确入口，不在读取时写回源文件：先严格按v1规则验证，再复制所有剧情/选择/计时/回忆/设置数据，保留PlaythroughId和实例ID；新增发现集合为空。实际游玩设置继续遵循现有本机Preferences优先规则，不因升级重置字号/音量。只转换汤店坐标及其ReturnContext：旧X/Y属于旧美术布局，映射到新图的安全锚点，不强行保持像素位置穿进新桌子。其他地图的旧坐标保留；桌面回忆的虚拟PlayerPosition仍沿用原值，实际返回位置来自转换后的ReturnContext。提示“旧进度可继续；汤店站位已适配新场景”，不重新发汤店会面、硬币或完成事件。

优先加载v2槽；若v2不存在才提供旧档升级。v2损坏、未知版本或读取错误时不悄悄退回较旧的v1，不自动新建覆盖；显示原因，并由用户选择既有保留副本/备份恢复流程。旧档损坏或未知版本同样不猜测迁移。v1自动/手动槽和各自备份分开验证与处理，不互换槽、不用坏主档覆盖有效备份。

首次保存升级结果写入v2对应槽，源v1主档/备份字节不变；升级或保存失败，原文件仍在、当前可继续或重试，不声称保存成功，也不通过失败强制返回菜单/退出。所有新档写入继续采用临时文件校验和原子替换；新游戏先保留该版本两槽，不能绕过未知版本保护。

新档有限但被家具变化占据的位置可以恢复到明确同场景安全点并提示；NaN、无穷、超出坐标范围、伪造版本/剧情/发现ID等无效数据必须拒绝，不能用“投影回地面”吞掉全部损坏。发现ID不上传云端，不扩展默认关闭的行为记录白名单。

未知或缺失锚点、导航配置、正式资源均给明确诊断并阻止该交互，不退回穿墙/漂浮的伪成功。场景加载失败保留原世界和进度；读档失败不取消原有可用会话。

全部验证与迁移测试仅用E:/游戏创作/顾行舟/test-output下的副本，不能操作真实user://存档证明迁移。运行时user://仍由Godot管理，项目文档/源码/素材/测试产物全部留在指定工程内。

## 8. 模块与数据流

| 模块 | 职责与依赖边界 |
| --- | --- |
| 场景导航配置 | 模式、地面多边形、占地障碍、入口/座位/安全点；编辑器静态节点与导出的同源数据须有一致性检查 |
| 二维移动与交互规则（Domain） | 归一化方向、二维距离、迟滞、已发现ID及版本/位置校验；不依赖Godot对象 |
| PlayerController/WorldView | 物理移动、方向动画、实际场景碰撞与脚部阴影；读取当前场景模式，不决定故事结果 |
| InteractionController/热点 | 当前世界限定的目标集合、可见性/遮挡、鼠标坐标与键盘目标；不按全局组误选已退出场景对象 |
| SoupSeatController | 到座位、动作与取消/恢复；成功后衔接现有主线，旧回调不得推进新会话 |
| DialogueController | 唯一阻塞对白会话及字幕排版；观察完整结束后请求发现记录，非阻塞气泡不提交剧情 |
| SaveRepository/升级适配 | v1严格读取、纯数据升级、v2写入和旧档保护；不依赖运行时Physics查询来反序列化 |

正常交互流：输入→当前Flow/场景模式检查→可见/可达目标→已有故事动作或可选观察→唯一数据事实提交→表现与必要保存。视觉动画和音效不能成为进度权威。

导航范围、障碍与安全点须在编辑器和Domain校验间有同源表示，并用测试比对；禁止维护两份互相不一致的矩形让物理可走、保存却失败。既有WorldView直接子节点搜索需适配Actors/Props分组，不能重排场景树后遗漏座位/出口。

## 9. 验收与非声明

实施计划需为每项行为新增失败后再通过的测试，不能直接删掉原横向套件。历史69规则/24引擎套件/234截图是基线结果，不是新版本已通过。

1. 移动：四向/斜向、斜行速度不额外增加、加减速、撞墙沿边滑行、不能穿桌椅、上下移动也触发脚步；其余两图横向回归仍通过。
2. 导航：入口、出口、座位、三观察点均可达；4:3与16:9无黑边/未绘制空区，人物与阴影比例不因窗口或Y位置改变。
3. 动作：坐下与起身逐帧检查体型/臀部/脚底；三动作真实选项入口、两个动效模式、手机冻结、Esc顺序、过期回调、F5/F9站姿恢复。
4. UI：20/24/32字号，1280×720、1920×1080、1440×1080；短对白不沿用278像素空面板，不遮脸/动作主体，长文和选项均可操作。
5. 鼠标：三个热点各可发现/重看/取消，UI点击不透传，缩放/相机偏移后点中正确物件，遮挡后不可点，E不隔桌触发。
6. 存档：v2上下位置往返、已发现ID持久化；v1自动/手动/备份、四币中间进度/完成/重放均可升级；源字节不变，未知/损坏/写入失败不覆盖，两槽不串档，三结果与完成事件不重复。
