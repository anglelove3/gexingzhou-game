日期：2026-10-14（北京时间，UTC+8）

状态：对话设计四节均已获用户认可；本文为待用户书面复核的正式规格。尚未修改运行代码、素材或真实存档，也未声称本功能已完成。

## 1. 意图、选择与成功标准

本子项目把现有横向的 `convenience_street` 升级为纯室外、可四向探索的环形生活街区。用户明确选择：

- 探索密度采用较完整街区，而非单纯任务通道；
- 不进入便利店或其他室内空间；
- 可选探索目标约 6—8 分钟；
- 空间采用“环形街区”，支路互相连通，减少原路折返；
- 现有交喜糖、前往汤店和返回小区的主线保持直接、清楚且不被探索阻塞。

成功标准：入口、Hey哥和汤店出口沿同一条东西向主街可直接到达；北侧生活环路、南侧后巷环路及东侧短支路形成三块探索区域；七处环境见闻、两位无名背景居民和轻环境声增加生活气息，但不编造现实人物经历、不新增奖励、支线、收集总数、Buff或隐藏结局。

主线直走目标为约 45—70 秒；完整探索目标为约 6—8 分钟。时间是试玩调优目标，不在实现前宣称已经达到。

## 2. 已核对的工程事实与本轮边界

当前 `ConvenienceStreet.tscn` 为 `1280×360`、`WorldMode.Horizontal`，玩家和三个交互目标都位于 `Y=280`：左侧返回小区、中央Hey哥、右侧前往汤店。`navigation.json` 对该场景仍使用横向模式，无地面多边形和障碍物。

工程已有并复用：

- 汤店与小区已经验证的 `Depth2D` 四向移动、斜向归一化、碰撞滑行、脚底排序和镜头策略；
- Godot静态具名节点、导航导出及场景/导航一致性拒绝机制；
- 鼠标或附近 `E` 观察、完整读完才记录、`Esc` 取消不记录的见闻机制；
- “今日记事”对稳定发现ID的只读投影；
- `schema 3 / vs01-0.3` 的严格读取、备份保护和明确复制升级流程。

本轮只升级便利店街。小区、汤店、手机、暂停、长椅、汤店动作、硬币回忆、三种回忆结果及主线阶段不重新设计。便利店外立面不可进入；不增加室内场景、自动寻路、背包、经济、战斗、AI对话或联网功能。

## 3. 空间骨架与静态场景结构

### 3.1 批准的环形布局

第一版世界尺寸为 `1600×720`。主街东西向贯通，入口、Hey哥、汤店出口都在主街；三块可选区域为：

1. **北侧生活环路**：从主街西中段向北，经旧门牌、报刊亭、自行车棚和排水沟，再由东中段回到主街；这是面积最大的探索区。
2. **南侧后巷环路**：从Hey哥西侧向南，经旧漆墙面和晾晒架，再从Hey哥东侧回到主街。
3. **东侧短支路**：位于主街东段，通往店外塑料凳，原路很短，不形成第二个出口。

第一版锚点使用世界局部坐标：

| 用途 | 坐标 | 约束 |
| --- | --- | --- |
| 小区入口 `entry` | `(100, 520)` | 合法地面；从小区进入时落点 |
| 安全点 `safe` | `(240, 520)` | 合法地面；无家具遮挡 |
| Hey哥站位 | `(800, 500)` | 主街可见，四周保留互动通道 |
| 汤店出口 `exit` | `(1500, 520)` | 合法地面；任务未满足时只提示 |
| 北环西/东连接 | `X≈380 / 1220` | 两端均与主街连通 |
| 北环上沿 | `Y≈220` | 家具底座之外保留至少一个角色直径通道 |
| 南环西/东连接 | `X≈620 / 1000` | 两端均与主街连通 |
| 南环下沿 | `Y≈650` | 不超出镜头与地面边界 |

连接坐标允许在实际美术对齐时小幅调整，但必须同时更新 `.tscn`、导航导出、见闻站位和测试期望，并在验收记录中写明；不能只放宽导航或只移动图像。

### 3.2 节点契约

根节点继续使用 `WorldView`，保留 `Backdrop`、`Interactions`、`Navigation` 与必要前景层。新增或调整：

- `DepthLayers/Actors/Player`、`DepthLayers/Actors/Hey` 及两位背景居民；
- `DepthLayers/Props` 下的报刊亭、自行车棚、晾晒架、店外家具及其他需要脚底排序的物件；
- `Navigation/GroundBoundary`、`Navigation/Obstacles` 与 `Navigation/Anchors`；
- 七个具名观察热点，点击形状与可见物件一致；
- 真正遮挡鼠标与人物的近景才放入前景层，不用整张透明图阻断交互。

美术、碰撞、热点、锚点和角色站位都写入 `.tscn`，C#只绑定行为、驱动状态并验证契约。缺少关键节点、ID重复、导航未导出或场景与导航不一致时，诊断并拒绝进入，不在运行时静默拼出另一套地图。

### 3.3 移动、遮挡与镜头

沿用当前四向移动数值、斜向归一化、加减速、快走、脚步声和三方向八阶段步态。玩家逻辑位置仍是脚底，障碍按底座而非整幅图像外接矩形；碰墙可以沿边滑行，不能持续原地踏步。

人物、Hey哥和背景居民按脚底Y排序；店面墙、报刊亭后墙等固定后景不参与错误的前景遮挡。16:9、16:10与4:3继续等比显示，不拉伸人物；相机跟随并限制在世界边界内，主线三点始终可通过移动找到。

## 4. 主线、环境人物与交互规则

### 4.1 主线不改写

小区进入后，玩家可沿主街直接找到Hey哥并完成 `candy.hey.delivered`；交付后继续向东进入汤店。玩家可以先探索再交付，也可以交付后回头探索。探索不会推进或回退 `SliceStage`，不会改变邀请、喜糖数量、对话选择、付款或回忆结果。

汤店出口在任务条件未满足时不切场，显示与当前目标一致的轻提示；返回小区出口继续有效。切场失败时保留玩家、任务和存档状态，不先写入目标场景坐标。

鼠标悬停轻描边，点击或在合法可达距离内按 `E` 打开同一观察内容。完整关闭阅读才写发现；`Esc` 中途取消不记录，重读幂等。UI、手机、对白、选择、暂停、日志、场景过渡和前景遮挡均阻止点击穿透。见闻不显示总数、不奖励数值、不改变主线。

### 4.3 背景居民与环境声

增加两位无名背景居民，仅在短路径内缓慢行走或停留；不接受互动，不出现名字、对白、任务、奖励或人物身世。阅读、暂停、失焦及“减少动效”开启时停止移动；恢复后从合法位置继续，不穿越障碍或挡死主街。

环境声使用原创或可重复生成的轻自行车铃、店外冰柜低鸣和远处脚步，不加入可辨认人声。声音遵守现有音乐/环境/音效音量及零值静音规则；静音不影响通关和发现记录。

## 5. 数据流与组件边界

1. `WorldView` 读取场景绑定和当前 `navigation.json`，校验通过后把导航交给玩家与交互控制器。
2. 玩家输入只更新合法的世界局部脚底坐标；稳定探索状态下由 `GameSession` 保存当前位置。
3. `InteractionController` 选择可达且未被遮挡的Hey哥、出口或观察热点；剧情动作仍交给 `QuestReducer`，发现只交给 `DiscoveryPolicy`。
4. `ObservationController` 完整结束阅读后调用 `GameSession.MarkDiscovery`；该调用幂等并触发当前版本检查点保存。
5. `JournalProjection` 只从 `Stage`、既有完成事实和 `DiscoveredIds` 投影，不建立第二份主线状态。
6. 场景切换先验证目标场景、锚点与任务条件；成功后更新 `SceneId` 和位置，失败则保持来源场景与原快照。

共享代码只做支持本轮所需的窄改动：允许任意 `Depth2D` 场景使用可达性、观察和Y排序；不顺手重构手机、汤店动作、回忆或其它无关模块。

## 6. 存档版本、复制升级与错误保护

### 6.1 新版本

本轮采用 `schema_version=4`、`content_version=vs01-0.4`，新目录为 `user://saves/vs01-explore-v4`。结构仍使用现有字段；版本升级是因为便利店街坐标语义和发现白名单变化，而不是增加奖励或人物事实字段。

冻结当前 `schema 3` 导航到 `content/vs01/compat/navigation-v3.json`：小区与汤店为当前二维布局，便利店街为 `1280×360` 横向、`Y=280`。v3读取和迁移必须使用冻结导航，不能先用新地图解释旧坐标。

### 6.2 升级优先级与位置映射

启动时优先当前v4主档/备份；任一v4槽存在，就不静默回退旧版。v4均不存在才检查v3；v3任一槽存在，就不越过它猜测v2/v1。更早版本沿用现有严格链路，在内存中逐级适配，不写中间版本文件。

用户从菜单明确选择“复制并继续”后才写v4。原v1/v2/v3主档、备份、偏好和文件哈希保持不变；自动档与手动档分别处理，不串槽。

合法v3便利店位置 `(X,280)` 先按冻结横向导航验证，再映射到新主街：保留可用的X，Y映射到主街安全线；若映射点被家具占用，则使用同场景 `safe` 锚点并提示位置调整。其它场景、回忆虚拟坐标及汤店 `ReturnContext` 按现有规则保留或适配。剧情阶段、邀请状态、计时、喜糖、已完成事实、六个既有发现、选择、回忆实例和设置全部保留；不会自动补写七个新发现。

### 6.3 严格失败保护

未知版本、重复字段、重复或未知发现ID、非有限坐标、越界坐标、错误场景及损坏JSON均拒绝，原档保留。结构合法且位于地面内、但被后改家具挡住的位置可在读取时回到同场景安全点；这一恢复不能用于掩盖越界或未知协议。

候选升级必须先完成来源读取、故事验证、位置映射、目标场景预检和v4编码验证，再原子写入。失败不得改变当前运行快照、删除来源、推进任务或留下可被误读的半个新档。

## 7. “今日记事”与发现顺序

`DiscoveryPolicy` 的v4白名单为现有六项加本轮七项，共十三项。`JournalProjection` 固定顺序：

1. 安置小区三项；
2. 便利店街七项，顺序与北环→南环→东支路一致；
3. 鸭血粉丝汤店三项。

只显示实际发现项，地点文案为“在便利店街看过，可回到场景再次观察”。当前目标和既有六段完成经历继续从原主线事实投影；日志阅读不移动玩家、不推进计时、不触发发现或保存。

## 8. 美术、音频、隐私与公开资源

保持当前暖色、秋日、带生活痕迹的半写实栅格方向。背景与需要碰撞/Y排序的物件拆分：报刊亭、自行车棚、晾晒架、店外塑料凳等必须有透明独立资源或清晰底座，不能既画在整图又重复摆放。

实施获得书面规格及计划批准后才制作正式资源。新资源、生成提示、来源、许可与SHA256写入项目记录；公开源码包加入必需文件及哈希检查。不得上传真人照片、私人故事原稿、真实联系方式/门牌、真实存档、本机配置、测试输出或另一游戏资料。公开仓库不等于素材已获商业发行认证。

## 9. 测试与验收门槛

- 入口、safe、Hey哥、汤店出口、七个见闻均可达，背景居民不堵死主路；
- 交喜糖前后、先探索/后探索、返回小区、前往汤店及三种回忆结果完整回归；

### 9.2 实渲染与人工待验

至少覆盖 `1280×720`、`1440×900`、`1024×768` 及字号20/24/32。画面矩阵包含入口、主街、北环、南环、东支路、Hey哥交付、汤店出口、每类观察、前后遮挡、背景居民和日志页面。按实际物理帧/动画状态等待，不把一次渲染等待当固定物理tick。

最终运行完整构建、全量规则/引擎套件、工具检查、公开资源/隐私拒绝探针及冷目录源码包验证。正常速度真人键盘试玩、主观美术、6—8分钟节奏和声音感受若未实际完成，必须写“待验”，不以自动截图代替。
