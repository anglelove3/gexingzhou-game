## 1. 意图、顺序与方案取舍

玩家应能离开聊天界面查看下一件要做的事，也能回看自己实际经历过的事和发现的生活物件。游戏仍以人生、爱与成长为核心，不把探索变成刷奖励或必须搜齐的清单；Godot本地场景可编辑，C#负责行为，兼容已有进度，完成实施后正常同步原GitHub仓库。

本次优先任务日志，再单独处理小区和便利店街的四向探索。此前汤店样板及手机已经实现，不重做；其它地图暂时仍是横向移动。

三种路径：仅扩大HUD提醒最省事，但无法回顾经历；建立新任务数据库、奖励和手动追踪更复杂且会增加双重状态；推荐从现有快照只读投影一个独立日志，满足查看和回顾，不改主线权威及存档版本。本规格采用第三种路径，等待用户确认具体范围。

## 2. 第一版玩家体验

入口名称“今日记事”，HUD提供可点击按钮，J打开；J或Esc及关闭按钮收起。现有HUD保留自动追踪的一条目标，不增加进度条、等级、奖励或总收集数。

三个页签：

- 当前：一条自动更新的目标，文字沿用GameSession.TaskText的现有语义。可显示已知地点提示，但不列未解锁的后续步骤。
- 经历：只显示已完成且已存入剧情事实的事项，按故事顺序排列，不展示未完成事项的灰色占位或百分比。
- 见闻：只显示DiscoveredIds中的已知物件名称，附“在鸭血粉丝汤店看过，可回到场景再次观察”。第一版不在日志复制整段观察台词，不引入第二份可漂移的描述库。

空态分别使用“还没有记下已完成的事”“还没有记下见闻。走走看看，也不必找齐。”，不暴露隐藏物件的名称和数量。每次打开默认当前页并回到顶部；浏览页签和滚动不保存，第一版不支持选择、取消或持久化手动追踪目标。

首段完成后的当前页沿用“今天先到这里 · 明天见”，明确当前试玩已完成，不生成尚未开发的第二天任务。已发生的回忆不评价玩家的食物选择，不暗示正确答案、身世或恋人后续。

## 3. 任务与见闻的事实映射

保持QuestReducer、SliceStage、CompletedActions、ChoiceCodes、InvitationState和DiscoveredIds作为现有事实来源。新增纯C#只读JournalProjection，不能调用TryDispatch、MarkDiscovery或存档写入；输出新只读列表，不把可变快照集合直接交给UI。

当前目标覆盖全部9个SliceStage，并保留InvitationPending/InvitationResolved下CarArrived两种提示，与现有HUD完全一致。将现有TaskText文字映射提取到一个共用纯展示入口；GameSession.TaskText保留签名并委托该入口，以免改变其它调用方。

经历条目只依据真实事实键，不用“枚举大小超过某阶段”猜测完成，不遍历原始ID显示给玩家：

| 正式事实键 | 显示事项 |
| --- | --- |
| invitation.meeting_complete:invitation-1 | 在小区门口见到了张大炮 |
| candy.hey.delivered:hey-1 | 把喜糖交给了Hey哥 |
| soup.meet:soup-seat-1 | 和张大炮坐下来聊近况 |
| memory.return:soup-1（并已存在memory.food.resolve:soup-1） | 想起了那碗汤 |
| soup.payment:soup-payment-1 | 张大炮结了这顿的账 |
| slice.complete:slice-1 | 听过明天的安排，今天先到这里 |

MemorySession.Begin已确认生成soup-{MemoryOrdinal+1}，首段第一次为soup-1。回忆条目只要求首次memory.return:soup-1及memory.food.resolve:soup-1两个事实都存在，独立于当前MemoryState是否已经被重看实例替换；重看只保留一条经历，不把soup-2等重看完成算成新增事项。不能仅从当前MemoryState.Completed或任意memory.return前缀推导首次已经完成。

不接电话但已经门口会面同样出现第一条经历；接电话本身不冒充已经见面。SoupMeet只是坐下，不冒充吃完、付款或回忆完成。只读投影支持这些中间状态，避免日志催玩家完成已完成的事情。

见闻固定白名单及排序：soup.sign→旧招牌，soup.menu→看看菜单，soup.note→柜台便条，沿用SoupShop.tscn正式Caption。只显示已发现项；取消观察不出现、重读不新增、F9载入较早档应消失。本规格不开放新发现ID或地图观察点。未知ID不进入日志，现有存档校验继续拒绝未知记录，不能用日志过滤代替存档验证。

## 4. 打开条件与互斥规则

第一版只在正常自由探索的Field状态开放：World有效，无Memory视图、未坐长椅、未坐汤店桌边或正在就位、无对白/选项/手机/暂停/设置/收尾卡/切场。HUD按钮只在可打开时可用；其它状态按J不创建叠层、不改变焦点、不取消当前动作。

因此阅读硬币回忆、坐姿或对白时不能同时翻日志，玩家需先按原有方式收起界面或起身。这是第一版明确取舍，不是承诺已经支持所有来源恢复。可在暂时离开未完成回忆、回到Field并起身后查看当前目标。

新增FlowState.Journal仅为临时UI状态，不进入WorldSnapshot或SaveCodec。打开后停止角色移动、邀请计时、主线活跃时间、E交互及鼠标热点；场景不退出、原角色坐标不变。Journal打开不替代PauseController.IsOpen，不复用Paused以造成其按钮或F5/F9混入。

J、Esc与关闭按钮只收起日志，恢复Field和仍有效的先前焦点。日志内Tab不打开手机，Enter不推进剧情，WASD和方向键不能移动角色；方向键仍可用于UI焦点。日志内F5/F9不保存或载入，需先收起再操作，以免读档重建时残留日志或焦点。长按J/Esc不重复打开关闭，遵循Echo:false。释放和重按按键遵循已有移动逻辑，不在关闭时注入移动。

日志阅读期间沿用AudioDirector.SetPaused(true)的真实语义：停止当前瞬态音效，音乐/环境声保持播放但音量乘0.35；关闭SetPaused(false)恢复正常设置音量，不重启主题，也不重播已经停止的来电音尾段。本次不扩展为音轨冻结/恢复系统。日志不能因改变Flow误触来电、会面或任务完成，不追加行为事件、不发送网络请求。失焦期间不推进计时或打开第二份日志。

缺少Journal绑定按SceneBindings既有路径明确诊断，不构造运行时临时节点掩盖缺失；不可用打开请求返回失败，保持原进度、原焦点。新场景必须与MainView正常初始化和F9重新实例化共同验收。

## 5. 编辑器与视觉

新增scenes/ui/Journal.tscn及scripts/JournalController.cs，在Main.tscn预存Journal实例和HUD/JournalButton。浅暖纸色面板、深色文字、细边框和轻半透明背景，与生活插画协调，不沿用厚金属边框，不贴一张整屏图片。无需生成新正式美术或新增第三方素材。

主要静态路径（相对Journal根节点）：Dim、Panel/Content/Title、Panel/Content/Tabs/Current、Panel/Content/Tabs/History、Panel/Content/Tabs/Discoveries、Panel/Content/BodyScroll/Body/Text、Panel/Content/BodyScroll/Body/Empty、Panel/Content/CloseButton、StartupError。Body为ScrollContainer唯一的VBoxContainer子节点，Text与Empty按内容互斥显示。列表第一版用预存Label/RichTextLabel排版，不运行时生成整套界面；所有容器、页签和字体样式可在Godot编辑。

面板居中留24像素安全边距，宽度最多900、高度最多720并受窗口限制。标题、页签和关闭按钮固定；正文使用独立ScrollContainer，字体继承20/24/32，不为容纳文本偷偷缩小。窄窗口/大字号允许页签分行或增加高度，正文滚动而非裁字；统一深色focus字色，不能再次白底白字。

鼠标滚轮、PgUp/PgDn、Home/End可读完整正文，Tab循环焦点不穿到世界，关闭按钮始终可达。HUD按钮锚定右上并位于暂停按钮左侧，1280×720默认参考宽130、高48、间隔12；两者不能覆盖左侧目标或被目标展开按钮遮挡。测试允许根据实际容器排版微调尺寸，不更改上述可操作性要求。

手机保留现有Frame/Content/Task具名节点，文字改为轻量“行程已记下，收起手机后按J查看”，不提供日志叠加入口，不把当前任务大段插入聊天。HUD仍用共用目标文字，保证玩家关手机后有提示。PhoneController的Open/Close及邀请通话逻辑不改；更新相应测试，不能删除时钟隔离、来源/焦点恢复或三个尺寸的大字号检查。

## 6. 存档、模块与边界

不新增快照字段、schema或保存目录。继续schema 2 / vs01-0.2和vs01-explore-v2，旧schema 1经已有明确升级入口继续使用。日志在打开时从当前快照重建；读早档、新游戏、备份恢复不会沿用上次进度的清单。不把任务投影另存JSON、不缓存跨会话完成状态。

模块边界：JournalProjection负责只读展示；JournalController负责静态节点、排版、按键、可打开性及焦点；MainView负责入口与唯一输入优先级，使用现有GameSession.Flow和AudioDirector接口。PlayerController/ObservationController继续依照非Field状态拒绝操作，必须回归验证而非假定。无需改QuestReducer、奖励数值、观察剧情、NavigationCatalog或SaveCodec校验。

本次不实现小区/便利店四向移动、自动寻路、任务领奖/分支生成、背包、全文搜索、地图箭头、日历时钟、未读任务红点、点击任务传送、微信账号或AI对话。不宣称完成三日游戏、商业发行或全部真人体验验收。
