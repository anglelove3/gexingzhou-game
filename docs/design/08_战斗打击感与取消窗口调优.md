# 战斗打击感、取消窗口与破势反应余量

北京时间 2026-11-18。目标是在既有街头战斗中展示招式节奏、操作成本与验证方法。用户确认范围；本轮初值、实现和测试由AI协作完成，不虚构独立手工制作或贡献比例。美术与音源继续沿用现有素材，来源见2026-11-13战斗资源记录与licenses。

## 规则与取舍

| 项目 | 调整 | 设计理由及代价 |
| --- | --- | --- |
| 玩家命中停顿 | 轻一/二/三为2/3/4帧，重击5帧，蓄力7帧 | 区分力度；停顿计入战斗总时间，不能只以DPS评价。空挥无停顿。 |
| 格挡停顿 | 当前玩家/敌人成功格挡最长2帧；敌方未挡轻/重仍2/4帧 | 格挡清晰但不重复拖慢节奏；旧配置保留原有重击格挡4帧。 |
| 命中后闪避取消 | 仅轻击有效非格挡命中，后摇满4帧起，24耐力/39帧CD | 留出确认反馈和出招承诺；不让空挥、被格挡或重击获得无成本保险。无敌仍为闪避第4至10帧。 |
| 守势 | 48→72逻辑帧 | 短棍27帧蓄力＋19帧前摇过于接近原守势长度。近距离受控边界为延迟24帧仍破势、25帧不触发。 |
| 身体与镜头 | 显示层约0.12秒展开已有逻辑击退，冲击图形约0.22秒，场景轻微位移 | 不改变判定坐标、击退总量或HUD位置；减少动效关闭这些动态反馈。 |
| 结算 | 即时保存，界面延迟0.32秒，减少动效0.18秒 | 保留最后一击；保存失败立即显示重试，展示期间不推进战斗计时。 |

输入缓冲仍6帧。停顿冻结逻辑状态，但接收缓冲；过早按键会按现有规则过期，不延长为无限取消机会。换招清除命中确认，多目标命中只进行一次闪避及扣费。HUD仅在实际耐力和冷却允许时提示衔接，冷却拒绝不再误记耐力不足。

`combat-impact-0.1`只更新平衡版本；普通战斗进度仍combat-v1，故事仍schema4。旧配置缺省守势48、停顿按旧招式规则、取消关闭；历史最快成绩继续按配置哈希隔离。

## 可复现入口

在项目根目录、.NET 8开发环境执行（输出只写test-output，不提交测试档）：

```powershell
New-Item -ItemType Directory -Force test-output | Out-Null
git show a3f7a1b818ee643bd40a418f0b02b7f56a4179e7:content/combat/combat.json | Set-Content test-output/previous-combat.json -Encoding utf8
dotnet run --project tests/DomainChecks -- --balance --reference-config test-output/previous-combat.json --output test-output/impact-comparison-fresh
dotnet run --project tests/DomainChecks -- --filter CombatImpact
```

输出目录必须为新的test-output子目录。源码中`CombatBalance.Sample`复用相同策略和步进，记录完整配置、哈希、策略文件SHA256及每波统计；正文结果不包含真实玩家存档。此前无效的guard-window.json已明确标为构造失败，不作证据；修正后的近距离逐帧诊断及全量回归为本轮依据。

## 实际体验验收

关注出手时机是否可读、轻重是否有区别、取消是否值得消耗耐力、短棍是否能在看清守势后完成蓄力。需用户正常速度连续试玩和试听后调整。自动测试、GPU截图、受控EXE按键不代替真人完整试玩或跨电脑兼容验证。
