# 拳脚对练

用户确认把拳脚连招放进街头练习第一波，沿用快拳手。第一波原有经验与解锁条件继续使用，战斗存档的波次 ID 仍为 `a1`。

| 输入 | 表现 | 设计 |
| --- | --- | --- |
| J → J → J | 快拳、转身拳、正踢 | 攻击有效阶段后可缓存下一拳，后摇第4帧接招。正踢沿用第三段伤害和击退，保留拳套回气规则。 |
| J → J → K | 快拳、转身拳、低扫腿 | 第二拳有效非格挡命中后开放。默认24耐力、4帧停顿、7/5/19帧前摇/有效/后摇。有效命中使普通敌人倒地28帧，再进入既有起身状态。 |

两条分支从同一转身拳收势过渡。分支消耗下一招的完整耐力，空挥/格挡不开放扫腿。正常独立K保留重击与蓄力。轻击命中后的闪避衔接沿用既有判定。

默认护手起始一套正踢连段为42耐力，低扫腿连段为48耐力。低扫腿动作的成本、范围和时序由招式表单独设置，伤害仍随攻击属性成长。以转身拳接触时按键为例，选正踢约18个逻辑帧后进入第三次命中判定，低扫腿约15帧，另计第二拳停顿。低扫腿击退10，正踢击退24。快拳手进入倒地与起身时沿用原有防追打保护。

新规则由第一波的配置开启。旧挑战快照缺少此字段时仍可加载旧规则，本轮的平衡版本及哈希用于区分新成绩。其余波次维持既有招式。

2026-11-19 的 `combat-footwork-0.2` 从第二拳预计接触前 4 帧开始接受提前 K，按键最多保留 4 个 60 Hz 逻辑帧，命中停顿冻结逻辑帧。只有有效命中且耐力足够才兑现，格挡或空挥会清掉提前输入，已有的有效 J 可以继续接正踢。旧配置省略 `sweepEarlyBufferFrames` 时继续使用 0 帧提前窗口。

验证覆盖早按J、停顿中缓存K、格挡/空挥、耐力不足、暂停清键、旧配置、实际按键和渲染。先完成源码与 Windows 候选验收，再同步 GitHub 和试玩包。

与前版做972次确定性配对尝试，共5832波。普通回放两版均199胜44败，生命继承连战均191胜52败，无超时。旧版机器人策略仍作为纵向回归输入，未主动选择扫腿，不能据此判断扫腿平衡。分支差异由实体按键用例在第一波验证，完整节奏需要真人试玩。

## 2026-11-20｜击退和倒地后的站位复核

在 `combat-footwork-0.2` 上使用发行规则 DLL，默认一级旧护手，对照两个开阔起手距离（约 31、40 单位）和一个右侧边界夹具。每个起手比较正踢、扫腿与六种后续操作。操作为原地停留、后退 12／24 帧、纵向横移 12／24 帧，以及横移 12 帧后在下一次预警时继续横移。36 个确定性场景各跑两遍，记录到快拳手第一次后续攻击的有效阶段结束。

| 观测 | 正踢 | 低扫腿 |
| --- | --- | --- |
| 开阔处第三击 | 15 伤害，推开 24 单位，剩余 58 耐力 | 10 伤害，推开 10 单位，剩余 52 耐力 |
| 从命中到双方可行动 | 玩家第 29 帧，快拳手第 24 帧。开阔样本原地等待时，玩家收招后 5–8 帧出现敌方预警 | 玩家第 28 帧，快拳手第 53 帧。玩家收招后可先移动 25 帧，默认移速下横移 12 帧可走 36 单位 |
| 开阔处移动 12 帧后停住 | 后退或横移均避开第一次后续攻击 | 后退或横移均延迟预警，停住后仍被下一拳打中 |
| 对手已贴右边界 | 末击实测位移为 0，移动 12 帧后停住仍受击 | 末击实测位移为 0，仍保有 25 帧先动时间 |
| 横移 12 帧，预警出现后继续横移 | 三个起手样本均避开第一次后续攻击 | 三个起手样本均避开第一次后续攻击 |

现有成本对应两种用途。正踢在开阔处配合立即撤步，能躲过这批样本的第一轮反击。扫腿给玩家先换位的时间，快拳手起身后的预警仍值得观察。建议先在第一波现有操作提示里教「扫倒后横移，快拳手再起手时继续移动」。待确认后验收两套连段、20／32 字号提示和晚输入边界。

Windows 发行 EXE 从主菜单以脚本按键完成两种收尾各接后退或横移，人工抽查录帧，四次均退出 0。数字来自上述确定性对照，Windows 录帧用于核对现场动作和站位。真人手感与异机兼容待验。
