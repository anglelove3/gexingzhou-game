# 葛行舟｜数值设计与平衡基线

V0.2评审稿｜2026-10-03｜配套游戏设计总案

**所有数值都是未实测的初始建议，不是“平衡已完成”。** 字段名、单位、范围和校准方法先固定，实测后改值。首段仅启用移动、交互、存档与特定事件；第二天预算、战斗和结尾画像属于后续设计。

## 1. 不是传统养成数值

没有等级、刷怪经验、饥饿倒计时、恋爱好感或“孝顺值”。需要的数值只有四类：可操作手感；有限时段；现实任务资源；用于结尾回顾的行为证据。玩家不因阅读慢、走路慢或拒绝战斗而失去主线。

## 2. 基础手感参数

世界逻辑画布暂定640×360，世界单位按逻辑像素计算；UI单独按1280×720设计，实际窗口伸缩。人物可见高度约64px，32px地形块；最终以角色动画实机试读为准。

| 参数ID | 初值 | 单位/约束 | 目的与校准 |
| --- | --- | --- | --- |
| move.walk_speed | 112 | px/s；建议测试96—128 | 640px约5.7秒，避免横穿一屏拖沓 |
| move.run_speed | 168 | px/s；约步行1.5倍 | 自由走动不消耗体力 |
| move.acceleration | 800 | px/s² | 从静止到步行约0.14秒 |
| move.deceleration | 1200 | px/s² | 松键约0.09秒停下，不滑过目标 |
| interact.radius | 40 | px；测试32—48 | 靠近可操作，不隔墙拿东西 |
| interact.hysteresis | 8 | px | 保持目标至48px再丢失，减少抖动 |
| interact.repeat_guard | 0.25 | s | 防双击；关键事件还须按ID幂等 |
| dialogue.min_advance_delay | 0.15 | s | 防触发交互的同一按键跳过首句 |
| dialogue.type_speed | 30 | 字符/s；范围0或15—60 | 确认键先显示全句，下一次才推进 |
| invitation.voice_delay | 20 | s，可操作状态累计 | 无操作开场也及时发来语音 |
| invitation.call_delay | 15 | s，语音送达后 | 在停顿中形成追问，不是真实计时惩罚 |
| invitation.car_fallback | 30 | s，来电后 | 不接也由张开车触发邀请 |
| memory.fade | 0.65 | s | 现实/记忆保持连续性；辅助可短至0.15 |
| phone.max_blocking_fx | 0.6 | s，后续手机故障模式 | 故障有上限，首段不随机误触 |

邀请计时在暂停、手机阅读、设置、对话与切场中停止；在移动或空闲中累计。玩家第一项非移动互动决定开场措辞，计时到点保底送达，不能要求“必须先点击某物”。同一阶段邀请只产生一次。

没有跳跃门槛；首段不设置强制平台跳跃或要持续奔跑才能完成的路段。对话时保留取消/离开规则，只有短转场锁移动。

## 3. 第二天：三个行动点，不是三分钟

预算初值：`day2.action_budget = 3`。每个深度行动成本1，完成后进入下一时段：早晨→下午→傍晚→夜晚。夜晚试音固定且成本0。开始行动前告知时段变化，完成时才扣一次；取消不扣。行动失败/中断时从该行动检查点重试，不重复扣点。

| 行动ID | 成本 | 前置条件 | 完成后 |
| --- | --- | --- | --- |
| errand.suit | 1 | 尚未取伴郎服 | 衣服妥当，晚上无衣服收尾 |
| errand.candy | 1 | 还有待送喜糖 | 白天送齐，夜晚无交接收尾 |
| errand.audio | 1 | 尚未搬音响配件 | 常规试音，不缺配件 |
| family.deliver_meal | 1 | 未送饭 | 送到父亲午班，得知荒地冲突 |
| family.stay_conflict | 1 | 送饭完成、冲突未解决 | 留下参与，奶奶叫停/谈妥后可继续陪伴 |
| family.farm_and_visit | 1 | 冲突后仍留下、奶奶邀请 | 一次连续陪伴：农活、祭扫、旧合照线索 |

“早晨送午饭”表述为准备并前往午班交接，行动结束已到下午，不把现实午饭钟点当扣点规则。争执解决中打/谈/找奶奶都只属于同一次行动，不叠加扣点。身份支线是三行动连续路径，不要求剩余第四点。深度行动中的必要合照、墓碑观察不另外耗点。

只有行动完成后时段才变化；即使进入傍晚，也允许走动、看普通物件、读信息，然后自行选择剩余行动。0点时深度行动不可开始，但可探索现时段普通内容，并通过明确入口进入酒店。玩家主动提前去酒店，会显示剩余点数和会暂交朋友代办的事项，确认才推进。

### 可达路线核算

| 路线 | 总成本 | 得到 | 代价 |
| --- | --- | --- | --- |
| 三项婚礼差事 | 3 | 全部准备妥当 | 父亲与奶奶自行处理，无完整身份证据 |
| 送饭＋两项差事 | 3 | 看见家庭处境 | 一项婚礼差事由朋友补位 |
| 送饭＋留下＋一项差事 | 3 | 参与冲突和收尾 | 两项差事补位，没有农活/祭扫完整证据 |
| 送饭＋留下＋农活祭扫 | 3 | 家庭深度线与身世证据 | 三项差事补位，夜晚必须承担一个具体收尾 |

奶奶与父亲线不能替换成“收集最多真相才是最佳结局”。没有走深度线也有完整主线。

### 未完成差事的后果预算

朋友会代办缺项，但保留对应差异。夜晚只出现一个需要玩家主动收尾的任务，选择优先级：音响配件→衣服调整→喜糖交接；其他缺项用简短台词/物件体现，防三个错误连续堆成惩罚关。每项分别记录`player_completed / covered_by_friend / followup_resolved`，不能把朋友代办伪记为玩家已完成。

收尾最长目标3分钟，不扣新行动点；不会让婚礼取消、不伤害家人、不扣结局职业资格。无玩家输入时提示逐级增强，不自动“假完成”。

## 4. 任务物件与婚鞋交换

首段不做可自由购买的货币经济。喜糖为剧情物件：持有数量按任务收件人配置，交付原子化执行，重复提交不能重复扣除或重复记录。汤钱由场景叙事处理，谁扫码成功只改变玩笑，不检查玩家是否“攒够钱”。

第三天暂定伴郎游戏红包为3枚提示筹码，最多每次提示花1枚；观察、聊天和帮忙均有不花筹码的可通路径。父亲给的随礼红包为独立任务道具，不能作为闯关货币消耗。该婚鞋方案仍需原第238题确认，不作为既定玩法。

若允许翻乱房间：翻乱状态只能触发现场调侃与收拾交互，不出现殴打、威胁、伤害伴娘或强制数值扣分。任何方法都不能损毁婚鞋使婚礼卡死。

## 5. 后续轻动作初值

首段禁用；三日Demo动作增量单独验证。现实冲突仅限定事件开放，不能随意攻击路人。以下用于一对一、短时、可退出的初测，不承诺最终手感。

| 项目 | 初值 | 规则 |
| --- | --- | --- |
| 玩家生命 | 100 | 场景退出/检查点重试恢复，不跨日伤病养成 |
| 玩家耐力 | 100 | 战斗使用，自由走路不耗 |
| 轻击伤害/耐力 | 12 / 12 | 轻击不能击中非战斗NPC |
| 轻击前摇/有效/后摇 | 0.12 / 0.08 / 0.25秒 | 单轮0.45秒；可否取消另做手感测试 |
| 闪避耗耐力 | 25 | 按下到第0.04—0.20秒无敌，总长0.35秒 |
| 闪避移动/冷却 | 40px / 0.8秒 | 不能穿墙或穿入NPC安全区 |
| 耐力恢复 | 22/秒 | 消耗后延迟0.7秒，空耐力不禁止停手/对话 |
| 一般对手生命 | 60 | 5次基础轻击；不以连打速度定义剧情成功 |
| 对手伤害/预警/间隔 | 8 / 0.65秒 / 1.4秒 | 动画、图标与声音都有预警 |
| 受击保护 | 0.6秒 | 防多人/重复碰撞连续锁死 |
| 超出战斗界线 | 提示离开 | 允许主动退出；不是失败结局 |

故事模式：受伤系数0.6，对手预警时长系数1.3；玩家生命降到20时由父亲/剧情打断事件结束冲突，不依靠反复死亡。标准模式：系数1.0，生命归零重试检查点，不丢剧情资源。非战斗路径始终可用，动作辅助不消除后续承担。

核算：无抵抗连中5击约2.25秒；实际有接近、预警、闪避与停顿，初测目标8—15秒一轮接触而非2分钟Boss战。5击消耗60耐力，恢复损失约需0.7+60/22≈3.43秒。40px/0.35≈114px/s，闪避不是高速赶路。若实际连打过快，先改对手退距/可击窗口与场景节奏，不盲目堆生命。

## 6. 五维行为证据，而非人格量表

沿用观察维度：探索/稳定、表达/沉默、连接/距离、责任/回避、接受/反刍。它们描述本轮游戏中的具体行动，不诊断玩家性格、疾病、家庭关系。两个端点不等于好与坏；重复查看照片也不能直接判定“反刍”。

只统计**预先定义的语义机会**，不按帧、点击量、奔跑次数累积。`event_id + opportunity_id + playthrough_id`去重；同一记录重新读档后不能加分，完整新周目另计。首段事件不对接受/反刍做结论。

评分仅作为后续候选回顾排序：对某维度的有效事件赋`v∈[-1,1]`，权重`w∈[0,1]`，描述量`S = Σ(wv)/Σw`。分母0则“证据不足”，不用0冒充平衡性格。某维度至少3个独立机会、跨2个场景才可以给一句描述；低样本只列行为、不贴标签。不设置五维总分、不依据S解锁职业。

| 语义事件 | 示例编码 | 可以解释 | 不可以解释 |
| --- | --- | --- | --- |
| old_sign.inspect | exploration=+1,w=0.5 | 查看了招牌 | 对人生一定更有探索精神 |
| hey.reply_by_action | expression取决于明确行动,w=0.5 | 说话/收手机/离开 | 停顿秒数就是内向程度 |
| family.stay | connection=+1,w=1 | 选择留下陪伴 | 没留下就是不爱家人 |
| errand.followup | responsibility=+1,w=1 | 为答应的事收尾 | 替代同伴代办也可记自己完成 |
| final_call.exit | acceptance=+1,w=1 | 明确尊重新生活后退出 | 看过旧相册就是无法放下 |

结尾最多3条回顾，每条引用已发生的具体场景；职业/生活计划由玩家明确选择。首段仅向开发者显示事件事实，不向玩家输出五维总结。

## 7. 最小本地事件字典

公共字段：schema_version、content_version、playthrough_id（随机本地ID）、sequence（严格递增整数）、scene_id、event_id、opportunity_id、choice_code、game_day、checkpoint_id。计时仅记录场景内累计可操作毫秒；暂停时间剔除，不默认记录真实时间/姓名/账号/机器标识。

| 首段事件 | 允许值 | 唯一性 |
| --- | --- | --- |
| invitation.resolve | answered / arrived | 每次邀请1条终态；可另记一次主动关闭 |
| candy.hey.delivered | delivered | 每周目1次 |
| soup.memory.enter | entered | 每次实际进入，与回忆序号绑定 |
| memory.coin.complete | completed | 每次回忆1次 |
| memory.food.resolve | take / wait / share | 每次回忆1次，不以超时强判wait |
| soup.memory.return | returned | 与进入配对 |
| slice.complete | completed | 每周目1次 |

等待必须为可确认的“先不动”行动/明确结束节点；玩家离开电脑不能被记录为人格选择。可用性耗时单独统计，不参与画像。事件记录与存档完成事件集合分开：关闭记录后任务依然能防重复。

## 8. 平衡与数据质量检查

每次参数变动记录版本、原因、对照数据和回滚点。测试顺序：技术流程通过→自己完成多路径→邀请3—5人做可用性访谈→再做较多人数验证，不从3个人推导市场结论。

| 检查 | 目标/方法 | 不达标时 |
| --- | --- | --- |
| 回忆进入/返回配对 | 同一序号各1条 | 先排转场和重复记录，不先分析情绪 |
| 喜糖一致性 | 持有+已交付=初始任务数 | 修任务原子性与读档 |
| 行动预算 | 3-已完成成本≥0，关键行动只扣一次 | 修状态，不加第四个隐形点 |
| 首段通关 | 所有测试路径可到终点 | 通关逻辑优先于美术精修 |
| 引导 | 多数初测者能自行交付；记录卡点 | 改目标提示/距离，不先要求看教程视频 |
| 首段时长 | 目标15—25分钟；暂停剔除，阅读者单列 | 太短补有意义互动，太长删重复走路 |
| 选择反馈 | 至少2种明确行动反馈不同 | 改反馈可感知性，不偷偷增加好感分 |

首段成功率需明确分母为“实际进入首段的参与者”，退出不全等于不喜欢；访谈与异常记录结合。路线或结尾偏好属于后续分析，本轮没有真实玩家样本和实际结果。
